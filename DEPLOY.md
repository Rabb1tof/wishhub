# Развёртывание WishHub

Рекомендуемый путь — [готовые GHCR-образы](DEPLOY-OPTIMIZED.md). Состав: API, frontend, PostgreSQL; браузерные процессы, Redis и фоновые задачи товаров отсутствуют.

Для сборки на сервере заполните `.env.example`, настройте домен и сертификаты в `./ssl` для существующего `nginx.conf`, затем используйте `docker-compose.prod.yml`. Файлы Compose не выпускают TLS-сертификаты самостоятельно.

При обновлении старой установки сначала выполните [переход и резервное копирование](docs/lightweight-rollout.md). API применяет миграции при запуске. API и frontend обновляются совместно; проверьте `/health` и создание карточки только с URL+именем. Сохраните PostgreSQL и аватары; не используйте `down -v`.

Для запуска без контейнеров задайте ASP.NET-конфигурацию из [CONFIGURATION.md](CONFIGURATION.md), запустите API под существующим менеджером процессов, соберите frontend и направьте reverse proxy на API и статические файлы. Сохраните маршруты `/api`, `/hubs`, `/avatars`. Дополнительная установка браузера не требуется.
