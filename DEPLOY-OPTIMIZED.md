# Развёртывание через GHCR и EasyPanel

Состав запуска: PostgreSQL, API, frontend. Registry compose получает готовые образы; Traefik направляет домен на frontend:80. Сервисы browser sidecar и Redis не нужны.

1. Сохраните резервную копию PostgreSQL и volume аватаров. Для старой версии выполните [порядок перехода](docs/lightweight-rollout.md).
2. Заполните переменные из `.env.example`, укажите `IMAGE_OWNER`, `IMAGE_TAG`, `PUBLIC_URL` и секреты.
3. Используйте `docker-compose.registry.yml` без локального override. Не публикуйте frontend:80 на host, занятый Traefik.
4. Обновите API и frontend совместно: контракт карточки изменён. Дождитесь `/health`, проверьте вход, ручное создание URL+имя, редактирование/очистку фото и цены, чужой вишлист и резервирование.

Публикация образов в GHCR происходит существующим workflow при push в main/тега; эта инструкция не выполняет публикацию или обновление сервера автоматически. Для локальной проверки готовых образов добавьте `docker-compose.local.yml` (5173/5050).

`pgdata` и `avatars` сохраняются. Не удаляйте volumes при обновлении. Старые redis/browser volumes можно вывести из состава запуска, но не стирать вместе с пользовательскими данными.
